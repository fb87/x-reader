# UI / Input / Library bug-fix pass

This pass was based on the hardware-adapted codebase and the original e-ink mockup.

## Root causes fixed

- **Empty-library mode disabled most commands.** When no EPUB could be opened at boot the app entered a separate infinite loop that only redrew a few screens. Settings changes, service actions, and normal footer semantics were therefore skipped. The normal application loop now runs even with zero books.
- **Stale empty library cache.** A valid zero-book cache was treated as authoritative forever. Empty caches are now rebuilt, and discovery scans the mounted card recursively rather than only `/books` when that directory exists.
- **Settings mapping incomplete.** Margins, paragraph spacing, alignment, and page-turn mode were displayed but were not handled by `cycle_setting()` / `quick_setting_for()`. They now modify the correct persistent value.
- **Footer was mostly decoration.** The three footer cells now share a central hit-test and dispatch to the same logical actions as physical buttons.
- **Portrait refresh transform was invalid.** The IT8951 display-area transform used the native width as a physical Y dimension, producing out-of-range refresh rectangles. The transform now maps logical portrait rectangles back to native 960x540 coordinates and validates the result before issuing the command.

## Visual alignment with the mockup

- Home changed from large 2-column launcher cards to compact editorial list rows.
- Selected list rows use light-gray focus instead of heavy black inversion.
- Status/footer chrome is lighter and closer to the mockup.
- Footer cells remain large touch targets while using the visual treatment from the mockup.

## Validation

The host test suite passes with `-Wall -Wextra -Werror -Wconversion -Wshadow`.
Hardware validation is still required for the IT8951 portrait waveform/rotation behavior and GT911 touch transform.
